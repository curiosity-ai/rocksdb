# BenchmarkDotNet: DbHeadToHead and DbAsync (final, default job)

Run 2026-11-03 08:03-08:46 UTC on the quiet 4-vCPU KVM VM (no other agents, nothing else running; 1-minute load
average 0.9 at the start, 1.6 at the end), right after the 5-repetition dbbench matrix (`2026-11-03-final-warm-r5.md`),
tree `cfb30f9`. **The VM's CPU differs from the 2026-11-02 run**: now "Intel Xeon Processor @ 2.10GHz" (family 6
model 207, AVX-512, AMX), then "Intel Xeon @ 2.80GHz"; absolute times are not comparable between the two files, the
managed / rocksdb-sharp ratios are. Command:

```bash
dotnet run -c Release --project bench/RocksDb.Managed.Benchmarks -f net10.0 -- --anyCategories DbHeadToHead DbAsync --cli /root/.dotnet/dotnet
```

BenchmarkDotNet's **default job** (pilot, 6+ warm-up iterations until stable, 15-100 measured iterations, outliers
removed), `[MemoryDiagnoser]`, .NET 10.0.14 x64 RyuJIT (x86-64-v4). Times are per operation (`OperationsPerInvoke`).
`Engine=RocksDbSharp` is the NuGet `RocksDB` 11.12 binding (native `librocksdb.so.11.12`); `Managed` is RocksDb.Managed.
`Allocated` `-` = 0 bytes per operation; 1-26 B are the amortized cost of rare pool / memtable arena growth (26 B per
100-entry batch = 0.26 B per entry).

## Summary

| operation | rocksdb-sharp | managed | managed / rocksdb-sharp | 2026-11-02 ratio |
|---|---:|---:|---:|---:|
| Put (memtable, WAL) | 4.12 µs | 2.98 µs | 0.72x | 0.57x |
| WriteBatch of 100 puts | 120.2 µs | 67.8 µs | 0.56x | 0.60x |
| Get from the memtable | 1716 ns | 765 ns | 0.45x | 0.49x |
| Get from a cached SST block | 2052 ns | 1133 ns | 0.55x | 0.35x |
| Get of a missing key (Bloom filter) | 416 ns | 125 ns | 0.30x | 0.28x |
| Seek + 10 Next | 3.97 µs | 0.98 µs | 0.25x | 0.26x |
| Seek + 100 Next | 28.19 µs | 5.86 µs | 0.21x | 0.21x |
| MultiGet of 16 keys | 27.35 µs | 17.05 µs | 0.62x | 0.52x |

`DbAsync` (sync / async, blocks in the block cache; page cache in parentheses): Put 2.75 / 2.87 µs (2.79 / 2.80),
TryGet 1.04 / 1.14 µs (2.07 / 2.30), Seek + 10 Next 1.45 / 1.44 µs (2.64 / 2.85), MultiGet(16) 15.2 / 15.3 µs
(33.6 / 35.7). Async costs 0-11% when every call completes synchronously (2026-11-02: 0-20%).
