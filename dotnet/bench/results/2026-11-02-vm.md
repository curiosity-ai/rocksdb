## Observations (single run, noisy shared VM -- treat differences below ~1.3x as noise)

- **P/Invoke overhead (rocksdb-sharp vs c-native)** is visible on the cheapest operations: readseq/readreverse
  (0.3-1 us per Next in C) cost 1.0-2.6x in rocksdb-sharp (`iter_next` + `iter_valid` + `iter_key` + `iter_value` are
  four transitions per entry), readmissing usually 1.6-2.4x, and 4-thread point reads with 100-byte values ~2.4x. Writes and SST point
  reads (5-15 us) are mostly within noise of C.
- **Managed sync** is at or below C for the write path (fillrandom/overwrite/deleterandom 0.5-0.9x: no P/Invoke,
  memtable insert fully inlined), memtable/bloom misses (readmissing) and readwhilewriting with 100-byte values;
  readrandom/multireadrandom are on par.
- **Managed is slower** on: reverse iteration (readreverse 1.3-4.6x), iteration over 1 KiB values (readseq/seekrandom
  2-5x), `flush` (1.3-3x, and allocates 2-8 MB per flush), and fillseq with 1 KiB values (~1.1 KB allocated per op:
  the memtable arena/WAL buffer grow path). `compact` is n/a (no compaction yet), so the managed LSM has more L0
  files for the read benchmarks than native (which compacts in the background).
- **Managed async** adds ~150-300 B/op of allocations on writes (PutAsync/DeleteAsync) and ~230 B/op on
  TryGetAsync, plus ~800-2900 B/op in async seeks (SeekAsync/NextAsync state machines); single-task async is
  1.5-3x slower than the sync API on cheap operations, while with 4 concurrent tasks writes (group commit) are on
  par with or faster than sync threads.
- Managed `MultiGet(IReadOnlyList<byte[]>)` allocates the result arrays (~130 B/op at 100 B values, ~930 B/op at
  1 KiB); there is no span/pooled MultiGet yet.
